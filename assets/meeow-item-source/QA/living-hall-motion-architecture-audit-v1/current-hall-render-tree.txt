Living Hall spatial/motion architecture audit V1 — current render tree

Evidence: index.html:5293-5575, 4164-4434, 11270-11490; js/meeow-map.js:1-116.

The live Hall is ordinary Vue/DOM, CSS and layered PNG images. It is neither Canvas nor SVG. Only the resident image is produced via a temporary Canvas-to-data-URL conversion after the Cat Renderer composes pixels (index.html:14191-14265).

Hall page (currentTab=lounge, loungeView=room)
├─ Hall header and actions (refresh, change Hall, Curator door)
├─ user status, accepted shared-scene feed/composer, holiday/guardian widgets
└─ display toggle
   ├─ text: responsive two-column resident cards with status/avatar
   └─ map: room tabs (dorm/living/dining) and stage (aspect-ratio 1)
      ├─ background.png, z=0
      ├─ groundLayers PNGs, z=1
      ├─ resident buttons, z=4, each with rendered cat PNG data URL or avatar fallback
      ├─ per-resident clipped occlusion overlays, z=5 when configured
      ├─ foregroundLayers PNGs, z=3 (draw order does not override cat z=4)
      ├─ dining fridge hotspot, badge/name/POI-label overlays
      └─ selected resident status card; Away residents listed outside stage

The Curator room has a separate CSS gradient/checkerboard anchor stage at index.html:4217-4258 and 5234-5247. It has no authored room-map PNG. This is an intentional future authoring case, not a production regression or MVP prerequisite.

Hall switching changes activeHallId and the visible resident filter; the same three map definitions/art sets are used across built-in and Custom Halls. Text/map mode and active room are localStorage presentation choices. The current map stage scales to container width with a square aspect ratio, clips overflowing content, and projects logical 1024 coordinates to percent. Resident sprite width is currently 72 CSS px, independent of stage width, so apparent world scale changes on narrow screens.
