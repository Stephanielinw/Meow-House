Living Hall spatial/motion architecture audit V1 — shared motion versus identity

Evidence: js/meeow-cat-renderer.mjs:1-82, 140-280, 355-500; js/meeow-resident-visual.js:1-45 and 292-385. Classifications: A shared timing/mapping, B per-body chassis, C authored per-motion-frame asset, D special identity handling. More than one class can apply.

Layer              Class  Why
Body silhouette    B,C    Four body geometries; every gait frame needs a legal contour/feet.
Head/face plane    A,C,D  Shared identity paint logic; directional/turning head geometry must be authored.
Bib/chest          B,C    Chassis material ownership differs with body and gait.
Face markings     A,C,D  Existing masks can map, but side/head-turn frames need directional masks.
Back/torso marks   A,B,C  Generic semantic colors, frame-specific region masks.
Socks/front legs   B,C,D  Separate left/right fields; leg pixels/occlusion change per step.
Rear legs          B,C,D  Same as front legs, with front/back gait order.
Ears               A,C,D  Type and inner/outer layers reusable conceptually; twitch/turn frames need art.
Tail               A,B,C  Tail type/mark data reusable; attachment and swing silhouettes per frame.
Eyes               A,C,D  Color layer shared, but visibility differs with facing.
Heterochromia      D      eyeLeft/eyeRight must follow anatomical identity after turns.
Coat palette       A      Per-resident color mapping over valid frame ownership masks.

Recommendation: one master timing, named gait phases, foot/attachment landmarks and layer-ownership specification; author the smallest valid frame chassis/masks per body type and direction as needed. Compose each resident's identity through those masks, then cache final frames. Do not promise a single ancestor bitmap can merely be recolored or stretched for every body. The static renderer is a strong architecture precedent, not proof that motion assets already exist.
