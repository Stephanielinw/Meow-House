E. GENERIC FOOD GAPS

Generic-safe Food coverage is 0. The current art is specific to permanent products.
The major useful closed-vocabulary gaps are:
- ingredient forms for fish, meat, egg, fruit, vegetable, and grain;
- broad meal forms for fish, meat, egg, grain, vegetable, and bread;
- broad snacks for fish, meat, vegetable, fruit, bread, grain, and dessert;
- generic dessert composition and fruit dessert;
- generic drink, hot mug, and fruit beverage.

Current taxonomy limitation:
- soup, stew, porridge, noodles, salad, dumplings, sandwich, pizza/flatbread, cookie,
  chocolate, pudding, jelly, yogurt, ice cream, tea, coffee, juice, milk, berries,
  citrus, and cheese are not object values.
- Several can be represented only by a broader dominant object/form pair. For example,
  soup and grilled meat may both become meat/food/meal/food; tea and coffee may both
  become mug/ceramic/beverage/food.
- The resolver does not score aliases or free text. Drawing several subtypes with the
  same tag tuple would not make them individually selectable; tie-breaking would choose
  one sprite ID deterministically.

Therefore Base Library V1 should draw broad archetypes that correspond to distinct
closed hint combinations, not multiple unreachable variations. More detailed food
subtypes belong to a future taxonomy/router design decision, outside this audit.

F. NON-FOOD GAPS

The largest current gaps match actual Explore/Away demand:
- broad travel trinket/charm;
- utility tool/equipment;
- paper map/document and physical letter;
- coin and key;
- bottle/container;
- stone, crystal, shell, branch, leaf, flower, herb, feather;
- small toy.

Lower-priority closed values can safely retain legacy icons for V1: stick, seed,
mushroom, gem, bone, book, scroll, photo, cup, jar, box, bag, basket, ring, necklace,
cloth, ribbon, rope, craft material, and other rare household forms.

G. CURRENT housefood RESOLVER ROLE

housefood:* eligible for generic resolver: YES.
Specific-built-in-art leakage risk: YES, confirmed.

Reason:
- registry contains only the 16 housefood entries;
- resolveItemSpriteCandidate filters by exact object and accepts score >= 12;
- object match alone is worth 12, so mismatched material/form/context can still pass;
- no canonical-only or resolver-ineligible flag exists;
- assignAutoVisualIdentity uses that registry for live Away/Mail/Explore items.

Concrete current examples:
- fish/food/meal/food resolves to housefood:salmon-steak.
- grain/food/meal/food resolves to housefood:chicken-oat-risotto.
- a generic dessert tuple resolves to one specific dessert by ID tie-break.
- a generic drink tuple resolves to one specific beverage by ID tie-break.

Follow-up architecture action (not implemented here): exclude canonical housefood entries
from generic auto-resolution, or introduce an explicit resolver eligibility/role field,
then register approved basefood/baseitem art as the generic candidate pool. Existing
builtin-sprite mappings must remain unchanged.
